# План изменений: безопасное хранение паролей и резервное копирование

## Проблема

1. **Пароли шифруются, но ключ не защищён** — `servers.key` лежит в открытом файле рядом с `servers.json`, и у `servers.json` права `0644` (читаем всеми). Любой с доступом к обоим файлам может расшифровать пароли.

2. **Нет резервного копирования** — `save()` просто перезаписывает `servers.json`, поэтому при сбросе/повреждении конфигурации серверы (и MSSQL-сервер, который был потерян) исчезают безвозвратно.

## Решение

### 1. Модуль хранения ключа (`common/key_store.py`)

Новый модуль для хранения Fernet-ключа с двумя бэкендами:

- **macOS Keychain** (по умолчанию на macOS): ключ хранится в системной связке ключей через `security` CLI
- **Файловый fallback** (для тестов/не-macOS): ключ хранится в `servers.key` с правами `0600`

Выбор бэкенда:
- Через `config.security.key_backend` (по умолчанию: `macos_keychain` на macOS, `file` иначе)
- Через переменную окружения `PARALLELS_SQL_ADMIN_KEY_BACKEND`

Миграция: при первом запуске с новой версией, если `servers.key` существует, его содержимое будет перенесено в Keychain, а файл удалён.

### 2. Интеграция в `ServerRegistry`

- Замена `_load_fernet()` на вызов `get_key()` из `key_store`
- Удаление работы с `servers.key` из `ServerRegistry`
- Добавление `backups_dir` для хранения резервных копий

### 3. Ротационное резервное копирование

При каждом `save()`:
1. Создаётся timestamp-копия `servers-<YYYYMMDD-HHMMSS>.bak.json` в `backups/`
2. Устанавливаются права `0600` на копию
3. Выполняется подчистка старых копий (оставляется `backup_count` штук)

### 4. Права доступа

- `servers.json`: `0600` (только владелец читает/пишет)
- `servers.key`: `0600`
- Все резервные копии: `0600`

### 5. Конфигурация (`config.ini`)

Новая секция `[security]`:

```ini
[security]
# Backend для хранения ключа шифрования: "macos_keychain" или "file"
key_backend = file

# Количество резервных копий servers.json для ротации
backup_count = 5
```

### 6. Обновления

- [`common/key_store.py`](common/key_store.py): новый модуль
- [`common/config.py`](common/config.py): добавлен `SecurityConfig`
- [`common/server_registry.py`](common/server_registry.py): интеграция `key_store`, резервное копирование
- [`config.ini`](config.ini): секция `[security]`
- [`.gitignore`](.gitignore): добавлен `backups/`
- [`tests/test_server_registry.py`](tests/test_server_registry.py): адаптация под новую логику

## Использование

### На macOS (по умолчанию)

Ключ автоматически сохраняется в Keychain при первом запуске. Пароли серверов зашифрованы и не доступны без аутентификации пользователя.

### На других ОС или для тестов

Установите `key_backend = file` в `config.ini`. Ключ будет храниться в `servers.key` с правами `0600`.

### Переменная окружения

Для тестов можно переопределить бэкенд:

```bash
PARALLELS_SQL_ADMIN_KEY_BACKEND=file python3 app.py
```

## Восстановление данных

Если `servers.json` повреждён:
1. Найти последнюю резервную копию в `backups/`
2. Скопировать её в `servers.json`
3. Перезапустить приложение
